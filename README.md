# hxyfront-62013 木结构榫卯构件测绘归档台

源提示词编号：8

古建筑木结构榫卯构件测绘的前端工作台，解决现场照片编号记在纸单上、回来对不上构件的问题：
构件记录建筑、编号、木材、榫型、截面与病害位置；病害登记近景与整体照片编号，
缺一项即停在「待补拍」，同一照片编号只能归属一个病害。

## 归档规则

- 必填项：建筑名称、构件编号、木材种类、榫卯类型、截面尺寸。
- 病害一旦登记，必须同时给出**近景照片编号**与**整体照片编号**，缺任一项 → 待补拍；近景与整体不能填同一编号。
- 同一照片编号在全部构件的病害中只能出现一次，重复占用 → 双方均判待补拍，并提示占用构件。
- 三种状态：**已归档 / 待补拍 / 待核对**（待核对中无缺项者标「可归档」）。
- 截面尺寸或病害位置在归档后被修正：照片编号**沿用**，记录退出已归档并提示**重新核对**，确认后可重新归档（快照刷新）。
- 关系视图**只收录已归档构件**；待补拍、待核对、待重核构件均不出现。

## 页面

- **构件清单**：按状态（待补拍/待核对/已归档）、建筑、榫型筛选，可按照片编号检索；点击行载入表单。
- **录入核对**：录入构件与病害信息，实时显示归档核对结果；「保存记录」与「核对归档」分开。
- **尺寸记录表**：解析 `180x240` / `直径320` 等截面文本，按估算面积排序，可只看待补拍。
- **病害标记图**：单栋建筑 SVG 示意图，病害点标注位置与近景/整体照片号，缺号或编号冲突用红点标记。
- **关系视图**：单栋建筑的梁—斗拱—柱搭接关系，边上标注榫型，仅含已归档构件。

数据保存在浏览器 localStorage，可一键恢复示例数据（示例中 C-12 缺整体照片号，即待补拍）。

## 代码分层

归档判断、保存与页面操作分开：

- `src/domain/archive.ts` — 归档判断纯逻辑（`evaluateArchive`）：缺项、待补拍、照片冲突、修正重核，无 React 依赖。规则由 `scripts/check-archive.ts` 覆盖（22 项断言）。
- `src/services/store.ts` — 保存层：localStorage 读写、保存、删除、写入/取消归档、示例数据。
- `src/components/` + `src/App.tsx` — 页面操作层：筛选、选表、切页签、调用保存与归档判断，自身不写业务规则。
